# あそびパック（じゃんけん・はやおし・おみくじ）

標準ホストに組み込んだ、ｽﾀｯｸﾁｬﾝと向き合って遊ぶ3つのMini Appです。
MODの追加、Wi-Fi、音声認識、AI契約は不要です。おみくじの「1日1回」だけは時計の同期が必要です。

## 開き方

- 顔をタップして AppBar を出し、アプリ一覧から「じゃんけん」「はやおし」「おみくじ」を選びます。
- ドロワーの「遊ぶ」→「じゃんけん」で、じゃんけんアプリが直接開きます。
  以前は手の形のアニメーションが止まらずに繰り返すだけでした。じゃんけんアプリが入っていない機種では、従来どおり手のアニメーションを表示します。
- ドロワーの「遊ぶ」→「おみくじ」でも開けます（おみくじが入っている機種だけ表示）。
- 左上の戻るボタンでいつでも終了できます。

## じゃんけん・あっちむいてホイ

1. 「開始」→「じゃんけん…」の合図のあと、グー・チョキ・パーをタップします。
2. ｽﾀｯｸﾁｬﾝの手は、あなたの手が決まった後に乱数で決まります。あなたの手を見て決めることはありません。
3. あいこなら「あいこで…しょ！」で選び直します。
4. 勝った側が「指す番」になります。「あっちむいて…ホイ！」で ←↑↓→ のどれかをタップします。
   - あなたが指す番：ｽﾀｯｸﾁｬﾝが同じ方向を向いたら、あなたに1点。
   - ｽﾀｯｸﾁｬﾝが指す番：あなたが指された方向を向いたら、ｽﾀｯｸﾁｬﾝに1点。
   - 方向が違えば「セーフ！」で次のじゃんけんへ進みます。3秒タップしないと、得点なしで次へ進みます。
5. 先に2点取った側の勝ちです。「もう一度」で再戦します。勝負がついた後、自動で次の試合は始まりません。

方向は画面を見ている人から見た向きです。画面の右は、ｽﾀｯｸﾁｬﾝ自身から見ると左にあたります。
画面のミニ顔は目の向きでｽﾀｯｸﾁｬﾝの向きを示し、指す番のときは矢印も表示します。

### 首の動き（任意）

- 初期状態は「動きOFF」で、起動のたびにOFFへ戻ります。画面だけで最後まで遊べます。
- 「動きON」にすると、ホイの瞬間に首を向けます（上：`look-up`、下：`look-down`、左右：`look-touch-left` / `look-touch-right`）。
  強度は 0.9 です。ON にしたときは首の向きこそが遊びの中身なので、メモリーの補助演出より大きく動かします。それでも `REACTION_LIMITS` の範囲に収まります。
  勝負がついたら、あなたの勝ちは `success`、ｽﾀｯｸﾁｬﾝの勝ちは `proud` を強度 0.3 で再生します。
- 会話・音声・Performance・別のReactionが動いている間は、首を動かさずにゲームだけ続けます。そのときは、じゃんけん中の案内行に首を休んでいる理由を表示します。ホイの最中は「指す方向」「顔を向ける方向」の案内を優先します。開始前と試合後は、動きボタンに「動き待機」と出ます。
- 終了や「動きOFF」でキャンセルするのは、このゲームが開始したReactionだけです。
- 実機での左右の向きと振れ幅はまだ確認していません。

試合の終了時に Mini App の結果イベント（スコアはあなたの得点）を1回だけ通知します。

## はやおしチャレンジ（反射神経）

1. 「開始」で5回1セットが始まります。
2. 「まだだよ…」の間（1.5〜4.0秒のランダム）に、パッドが緑に変わり短い音が鳴ったら、頭のタッチパネルか画面のパッドをタップします。
3. 指が触れた瞬間までの時間（ms）と評価（いなずま級／はやい！／いい感じ／のんびり）を表示し、1.3秒後に次の回へ進みます。
   - 緑になる前、または合図から100 ms未満のタップは「フライング！」になります。
   - 合図から1.5秒以内にタップしないと「おそかった…」になります。
4. セットの最速記録が自己ベストより速ければ「自己ベスト更新！」と表示し、`sc_quicktap/state` に保存します。
   保存できるのは100〜1500 msの整数だけで、壊れた値は読み込み時に無視します。保存に失敗した場合は画面に表示します。

- 画面のパッドは押し始め（onTouchBegan）で判定します。頭のタッチは50 ms周期で読むため、画面より最大で約50 ms遅く計測されることがあります。
- 「音OFF」にしても、色の変化だけで遊べます。会話・音声・Performance・Reaction 中は音を出さず、「音は待機中」と表示します。サーボは動かしません。
- セット完了時に Mini App の結果イベント（スコアは成功回数）を1回だけ通知します。

## きょうのおみくじ

1. 「おみくじを引く」で箱を振る演出（約1.2秒）のあと、結果を表示します。
2. 結果は大吉・中吉・小吉・吉・末吉のどれかです（凶はありません）。あわせて、ラッキーアクション（8種）、ラッキーカラー（8色）、ｽﾀｯｸﾁｬﾝのひとことを表示します。
3. 時計が同期済みのときは、タイムゾーン設定の日付で1日1回です。結果は `sc_fortune/state` に version 1 の JSON で保存します。
   同じ日に開き直すと同じ結果を表示し、日付が変わるとまた引けます。
4. 時計が未設定の場合は保存せず、何度でも引けます。その旨を画面に表示します。

任意演出は「暮らし工房」→「工房の設定」に従います（初期値はどちらもOFF）。
「小さな仕草」がONなら、大吉・中吉は `success`、それ以外は `yes` のReactionを再生します。「短いお知らせ音」がONなら、短い音が鳴ります。
おみくじはゲームではないため、結果イベントは通知しません。

## 既存機能との関係

- 表示中はCompanionの待機動作を止め、終了・登録解除で再開します。ゲームが作ったタイマー、頭タッチの購読、短い音、Reactionはすべて解放します。
- Virtual Pet MOD、集中タイマー、他のMini Appと併用できます。Petへの経験値連携は追加していません。
- 旧4 MB M5Stack（タッチ入力なし）にはフラッシュ容量を守るため含めません。リズムまねっこと同じ方式です。
  文言も `host/app/strings/*.json` ではなく [play-pack-strings.ts](../host/app/play-pack-strings.ts) に置いています。この方式なら、除外した機種では文言の容量もかかりません。
- Webシミュレーターでは、自己ベストとおみくじの結果をブラウザの localStorage に保存します。
- `play-pack-host` は `main.ts` から `Modules.importNow('play-pack-host')` で名前を指定して読み込みます。
  WASM ホスト（JavaScript スタック 512 スロット）は、起動時の同期処理の時点でスタックの余裕がほとんどありません。`main.ts` に静的 import を足しただけで XS の stack overflow になることを確認しています。
  preload はしません（preload なしで WASM ホストが起動し、play-pack の e2e が通ることを確認済みです）。おみくじの任意演出（暮らし工房の設定）は、結果を表示した時点で `workshop-service` を名前で解決します。
- 3つのアプリが一覧から開けること
- じゃんけんでホイまで進めること
- はやおしが5回で終わり、自己ベストを保存すること
- おみくじを1日1回保存し、再読み込み後も同じ結果を表示すること
- Petと併用できること

CoreS3実機では、次の項目を個別に確認して記録してください。ビルドや自動テストが通っただけでは、実機で確認できたことにはなりません。

- [ ] じゃんけん：動きONで、ホイの首の向きが画面の矢印・目の向きと一致する（左右の符号）。可動域と復帰も確認する。
- [ ] じゃんけん：会話中は首が動かず、首を休んでいる理由が表示される。終了すると首が正面に戻る。
- [ ] はやおし：頭タッチと画面タッチの両方で記録が出る。音量と、合図の音・色の同期を確認する。
- [ ] おみくじ：時計同期後に1日1回に制限され、電源を入れ直しても同じ結果が出る。日付が変わると引ける。
- [ ] 3つのアプリとPet・集中タイマーを併用し、戻るを10回繰り返しても待機動作が復帰する。

## XS のキー数の上限（`not enough keys`）

xsl（リンカー）は、プロパティ名などの識別子（キー）を最大 8192 個までしか持てません。CoreS3 のリリースビルド（`m5stackchan_cores3`）はあそびパックの追加前で 7916 個、追加後で 8087 個です。余裕は約100個しかありません。
オブジェクトのプロパティ名と `#private` フィールドはキー1つになります。これを超えると、リンク時に `Error: not enough keys` で失敗します（Bundle の CI で実際に起きました）。

- メッセージは `play-pack-strings.ts` に「`key=message`」の行として持ち、実行時に `Map` へ読み込みます。オブジェクトにすると約110個のキーが増えます。
- 新しい機能を足すときは、`firmware/` で `npm run build:m5stackchan_cores3` 相当のリンクが通ることを確認してください。ESP-IDF がなくても、リンクの手順（`xsl`）だけなら再現できます。
