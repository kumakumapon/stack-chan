# リアクションとパフォーマンス

[English](./reactions-and-performances.md)

リアクションは感情を表現する短い名前付きジェスチャーであり、開始からリセットまでをタイムラインで再生します。パフォーマンスは、話す、歌う、リアクション、動きをひとつの絶対時刻で分単位で調整する振り付けです。

どちらも内部タイムラインクロックとホストが所有するステージで動作します。MODやエージェントツールは名前でのみ要求できます。生のサーボ角度を渡すことはできません。なでなでとIMU駆動の挙動は変わりません。

## リアクション

リアクションは数百ミリ秒から数秒間、顔、手、頭、エフェクトがタイムラインで変化し、その後リセットされます。

### リアクション名

8つの名前付きリアクションが利用可能です。

| 名前 | 表現 |
|------|-----|
| `yes` | 楽しそうなうなずき |
| `no` | 疑わしい横振り |
| `greeting` | 楽しそうな手振りとハートエフェクト |
| `thinking` | 疑わしい手をあご触れるポーズと汗 |
| `delighted` | 楽しそうなチアと揺れる頭 |
| `sleepy-yawn` | 眠そうなあくびと目を閉じる |
| `success` | 楽しそうな拍手と緑色のライト |
| `failure` | 悲しそうに頭を下げ、青いライトと涙 |

### リアクションの再生

`context.reaction.play(name, options?)` を呼び出します。

```js
const result = context.reaction.play('greeting', { intensity: 0.8, restore: true });
if (!result.ok) {
  trace(`リアクション失敗: ${result.error}`);
}
```

`play()` は成功時に `{ ok: true }` を、失敗時に `{ ok: false, error }` を返します。エラーの理由は、不明な名前、検証に失敗したタイムライン、またはパフォーマンス再生中です。別のリアクションの再生中に呼ぶと、そのリアクションを中断して置き換えます。

### リアクションオプション

- **intensity** (0–1、デフォルト 1): 頭の動きの幅をスケールします。intensity 0.5 のリアクションは通常の半分の幅で頭を動かします。
- **restore** (boolean、デフォルト true): リアクション終了時に顔、手、エフェクト、頭の位置をリアクション前の状態に復元します。`false` の場合、リアクション終了時の状態のままになります。

### リアクションの制御

- **cancel()**: 実行中のリアクションを停止し、ステージを直ちに復元します。リアクションが実行中の場合は `true` を返し、実行中でない場合は `false` を返します。
- **status()**: `active`（現在実行中の `ReactionName`、またはリアクション実行中でない場合は `null`）と `startedAt`（起動から経過したミリ秒、またはリアクション実行中でない場合は `null`）を含むオブジェクトを返します。

### リアクション制限

ホストはすべてのリアクションにこれらの制限を適用するため、MODやエージェントツールはこれらを超過できません。

- 頭ヨー角: ±π/6 ラジアン（±30 度）
- 頭ピッチ角: ±π/8 ラジアン（±22.5 度）
- 頭の動き時間: 150–3000 ミリ秒
- 頭ターゲット: 最低 150 ミリ秒間隔
- フレーム: リアクションあたり最大 48 フレーム
- 総リアクション時間: 最大 15 秒

なでなでとIMU駆動の挙動はこれらの制限を受けず、リアクション再生の影響を受けません。

## パフォーマンス

パフォーマンスは、話す、歌う、リアクション、頭の動きをひとつのタイムラインで調整した振り付けのシーケンスです。すべての cue はパフォーマンス開始からの絶対時刻で発火するため、低速なサーボ動作やTTSへの長い手渡しが他のパフォーマンスをずらすことはありません。

### パフォーマンス名

4つの名前付きパフォーマンスが利用可能です。`greeting`、`happy-dance`、`cheer`、`sing-twinkle` です。

### パフォーマンスの再生

`context.performance.play(name, options?)` を呼び出します。

```js
const result = context.performance.play('happy-dance', { intensity: 1.0 });
if (!result.ok) {
  trace(`パフォーマンス失敗: ${result.error}`);
}
```

`play()` は成功時に `{ ok: true }` を、失敗時に `{ ok: false, error }` を返します。エラーの理由は、不明な名前、または検証に失敗したタイムラインです。別のパフォーマンスの再生中に呼ぶとそれを中断して置き換え、直接開始されたリアクションもキャンセルします。

### パフォーマンスオプション

- **intensity** (0–1、デフォルト 1): パフォーマンス内の頭の動きの幅をスケールします。
- **restore** (boolean、デフォルト true): パフォーマンス終了時に顔、手、エフェクト、頭の位置をパフォーマンス前の状態に復元します。`false` の場合、パフォーマンス終了時の状態のままになります。

### パフォーマンスの制御

- **cancel()**: スケジューリングを停止し、実行中のリアクションをキャンセルし、ステージを直ちに復元します。TTSに渡された話す・歌うはTTS内で完了します（音声機能に停止機構はありません）。パフォーマンスが実行中の場合は `true` を返し、実行中でない場合は `false` を返します。
- **status()**: `active`（現在実行中の `PerformanceName`、またはパフォーマンス実行中でない場合は `null`）、`startedAt`（起動から経過したミリ秒、またはパフォーマンス実行中でない場合は `null`）、`nextCue`（次に発火する cue のインデックス、またはすべての cue が発火した場合は cue の総数）を含むオブジェクトを返します。

### Cue タイプ

パフォーマンス cue は次をトリガーできます。

- **reaction**: 現在のステージでリアクションを名前で再生します。
- **motion**: 名前付きの頭の動き（nod、shake、sway-left、sway-right、bounce、look-up、look-down、head-left、head-right、center）を再生します。
- **head**: ヨー角/ピッチ角と期間で頭のターゲットを直接指定します。
- **speech**: 使用中の TTS で文字を話します。一度開始されると停止できません。下の cancel 同意を参照してください。
- **song**: 使用中の TTS が歌唱に対応している場合、raw stackchan-voice koe 記法を歌唱します。
- **emotion, hand, effect, light**: 顔の状態、手のアニメーション、エフェクト、またはLED色を直接変更します。

### 動き

パフォーマンス内では 10 個の名前付きの頭の動きが利用可能です。

| 名前 | アクション |
|------|----------|
| `nod` | クイックな上下のうなずき |
| `shake` | 左右の頭振り |
| `sway-left` | 頭を左に傾ける |
| `sway-right` | 頭を右に傾ける |
| `bounce` | クイックな上下のバウンス |
| `look-up` | 上を見る |
| `look-down` | 下を見る |
| `head-left` | 頭を左に向ける |
| `head-right` | 頭を右に向ける |
| `center` | 中央に戻す |

### タイミングと絶対時刻クロック

すべての cue は絶対 `at` 時刻（パフォーマンス開始からのミリ秒）で発火し、前の cue からの遅延ではありません。これにより、サーボ動作やTTS渡しが予期より長くかかった場合でも、パフォーマンスはビートに合ったままになります。

**キャッチアップウィンドウ**: クロックがスケジュール時刻から 1000 ミリ秒以上遅れた場合、そのウィンドウを超えた cue はバースト再生されるのではなくスキップされます。これにより、停止したクロック（例えば長いTTSチャンクやビジーなサーボトランザクション）がパフォーマンスを半分の速度で再生しているように見えることがありません。

**ウィンドウ内の遅延した cue**: Cue が遅延していますがキャッチアップウィンドウ内にある場合、それでも発火しますが、プレイヤーは発火の遅延を記録します。これによりパフォーマンスはビートに合ったままになります。

### 復元と cancel 同意

パフォーマンスが終了するか cancel される場合。

- **頭の位置**: パフォーマンス前のポーズに戻され、最大 200 ミリ秒で安定します。
- **顔、手、エフェクト**: 直ちに復元されます。
- **話す・歌う**: TTSに既に渡されたものは完了します。音声機能に停止機構がないため、`cancel()` はそれを中断できません。これは意図的な設計です。単語の途中で停止するとグリッチのように聞こえます。TTSが忙しい（例えば長い文字を話している）場合、次のパフォーマンスは完了するまで開始できません。

## エージェントツール

リアルタイムエージェントセッションは、リアクションとパフォーマンスをトリガーするための 2 つのツールを呼び出せます。

- **stackchan.react**: `{ name: REACTION_NAMES のうち 1 つ、intensity?: 0..1 }`
- **stackchan.perform**: `{ name: PERFORMANCE_NAMES のうち 1 つ、intensity?: 0..1 }`

これらのツールは MOD から `context.reaction.play(name, { intensity, restore: true })` と `context.performance.play(name, { intensity, restore: true })` を呼び出すのと同等です。

## MOD でリアクションとパフォーマンスを使用する

MOD はこれらの機能を namespaced API として受け取ります。

```js
export default async function onContextCreated(context) {
  // リアクションを再生
  const reactionResult = context.reaction.play('success');
  if (reactionResult.ok) {
    trace('success リアクション開始\n');
  }

  // ステータスを確認
  const status = context.reaction.status();
  trace(`アクティブなリアクション: ${status.active}\n`);

  // 必要に応じてアクティブなリアクションをキャンセル
  const wasCancelled = context.reaction.cancel();
  trace(`リアクションが実行中でしたか? ${wasCancelled}\n`);

  // パフォーマンスを再生
  const perfResult = context.performance.play('greeting', { intensity: 0.9 });
  if (perfResult.ok) {
    trace('greeting パフォーマンス開始\n');
  }
}
```

リアクションやパフォーマンスが実行中と想定する前に、結果の `ok` フィールドを確認してください。

## Web シミュレーターで試す

Web シミュレーターには、リアクション/パフォーマンスカードが含まれており、次のことができます。

- 名前でリアクションやパフォーマンスを選択してトリガーします。
- intensity スライダーを調整します。
- 3D モデル上で顔、手、エフェクトが応答するのを確認します。
- 実行中のリアクションやパフォーマンスをキャンセルボタンで cancel します。
- ライブステータスと cue 数を表示します。

これを使用するには、シミュレーターを実行し、コントロールパネルでリアクション/パフォーマンスカードを探して、リアクションやパフォーマンスをトリガーしてください。シミュレーターはリアルタイムでファームウェア WASM ビルドからステータスをポーリングします。

## ハードウェア検証

すべてのリアクションとパフォーマンスのハードウェア検証は現在保留中です。タイミング測定、頭の範囲、サーボ負荷は物理デバイスで検証されています。
