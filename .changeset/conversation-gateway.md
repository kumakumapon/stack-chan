Add a Conversation Gateway (`gateway/`): a resident service that sits between Stack-chan and an interchangeable Agent Backend — echo, OpenAI, or any Hermes-compatible HTTP + NDJSON agent — so the robot is never bound to one LLM or cloud. It owns conversation sessions, the media plane (PCM16 VAD/STT/TTS), the merged `ChatTool`-compatible tool registry (Gateway-hosted MCP tools plus device-hosted `stackchan.*` embodiment tools), and the `approval.request → presented → response → resolved` handshake, all reachable through a new Gateway Dock (`firmware/host/app/docks/gateway/`) selected with `conversation.backend = 'gateway'`.

The Gateway is deliberately not a new protocol stack: it speaks the same `stackchan.event.v1` control plane and the same realtime control plane (`session.update`, `response.function_call_arguments.done`, ...) the Android USB Dock already speaks over USB, just carried over WebSocket instead. That reuse means `RemoteConversationSession`, `createRealtimeSession()` and `createRemoteSessionRuntime()` needed no changes, Direct-mode `ChatService` is untouched, and device-hosted embodiment tools need no sideband message type of their own — the robot advertises them in `session.update` like any other realtime tool. Only what that existing pair of contracts genuinely lacked — the handshake, capability negotiation, the media plane, transcripts and agent errors — became the new `stackchan.gateway.v1` sideband, with independently maintained mirrors on the Gateway and the firmware so the device copy stays free of Node types.

Text conversations work end to end today, including device-hosted embodiment tools, MCP tools, approval, and reconnect with backoff. Two things are deliberately deferred: continuous on-device microphone capture (the Gateway's media plane and VAD/STT pipeline are ready, but the firmware has no streaming mic path yet — it needs an audio worker like the USB Dock's) and frame-by-frame audio playback (a streamed turn is buffered and played back whole on `audio.completed`, since Piu has no PCM sink that can be fed incrementally). None of this has been exercised on physical hardware yet. See `docs/specs/conversation-gateway.md` for the full spec.
