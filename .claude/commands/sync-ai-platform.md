# AI Platform 設定更新プロンプト

対象リポジトリに導入済みの AI Platform 設定を、プロジェクト固有のルールを壊さずに差分確認して手動で最新化する。自動同期Workflowや同期用トークンは使用しない。

## 依頼形式

```text
同期 owner/repo [PR作成]
```

`PR作成` がある場合だけ、対象リポジトリの作業ブランチで同期差分を作り、ドラフト Pull Request を作成する。既定ブランチは直接変更しない。

## 手順

1. 対象リポジトリの `AGENTS.md`、`CLAUDE.md`、`.claude/`、GitHub テンプレート、Workflow、既存PRと、AI Platform の最新テンプレートを比較する。
2. 更新候補のうち、対象リポジトリの固有設定と衝突しない差分だけを選ぶ。`AGENTS.md` は AI Platform マーカー区間だけを更新し、マーカーがない場合は上書きしない。
3. `CLAUDE.md`、独自のコマンド、CI、Issue/PR テンプレート、依存導入フックは、対象リポジトリ側の固有設定を優先する。内容の置換が必要な場合は、差分・影響・復元方法を明示する。
4. Secret、トークン、環境変数の値、CI 失敗ログを同期しない。外部リポジトリへのログ送信や権限拡大を有効化しない。
5. 更新対象として選んだ差分を、対象リポジトリの固有設定を壊さないか、マーカーのない `AGENTS.md` や独自のコマンド・CI・フックを上書きしないか、置換する場合に復元方法を示せるかの観点でレビューする。この同期は対象リポジトリのエージェント挙動設定そのものを変更するため、影響はコード変更より大きくなり得る。Critical または High 相当の懸念がある場合は、解消するまで手順1〜5を繰り返してから更新に進む。
6. レビューを通った範囲だけを、対象リポジトリの作業ブランチで更新する。
7. 変更する場合は設定ファイルの構文、リンク、必要な検証コマンドを確認する。実行できない検証は理由を報告する。
8. 更新した差分を、固有設定の保持、Secret の非混入、設定ファイルの構文の妥当性の観点でレビューする。Critical または High 相当の指摘がある場合は対応し、指摘がなくなるまで手順6〜8を繰り返してから完了とする。

## 完了基準

- 更新したファイルと意図的に更新しなかったファイルが区別されている。
- プロジェクト固有の記述、認証設定、デプロイ設定、Secret は保持されている。
- `PR作成` がある場合だけドラフト PR を作成し、差分・検証・リスクを記載している。

## 禁止事項

- Secret、トークン、環境変数の値、CI 失敗ログを同期しない。
- 外部リポジトリへのログ送信や権限拡大を有効化しない。
- 自動同期Workflowや同期用トークンは使用しない。
- `AGENTS.md` はマーカーがない場合は上書きしない。

## 報告形式

```md
## 参照した AI Platform のリビジョン
- <内容>

## 比較結果
- <内容>

## 変更一覧
- `<path>`: <内容>

## 保留理由
- なし / <内容>

## 検証結果
- `<command>`: 成功 / 失敗 / 未実施（理由）

## セルフレビュー
- 計画: なし / [重大度: Critical / High / Medium / Low] <指摘と対応>
- 差分: なし / [重大度: Critical / High / Medium / Low] <指摘と対応>

## PR
- <URL または未作成理由>
```
