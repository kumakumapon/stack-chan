# リリース準備プロンプト

対象リポジトリのリリース準備を、既存のバージョニング・公開・デプロイ方針に従って整える。リリースの公開、タグ作成、デプロイは行わない。

## 依頼形式

```text
リリース owner/repo [PR作成]
```

`PR作成` がある場合だけ、リリース準備用の変更を作業ブランチに作成し、ドラフト Pull Request を作成する。

## 手順

1. `AGENTS.md`、README、パッケージまたは配布設定、変更履歴、リリースWorkflow、既存タグ・Release・Open Issue/PR を調査する。
2. 既存のルールに従い、リリース対象・現在のバージョン・未公開の変更・利用者影響・必要な移行を整理する。
3. 整理したリリース対象・バージョン方針・利用者影響・必要な移行を、要求との整合性・見落とし・実現性の観点でレビューする。Critical または High 相当の懸念（バージョニング規則の根拠不足、未公開変更の取りこぼし、互換性を壊す変更の見落とし）がある場合は、解消するまで手順1〜3を繰り返してから更新に進む。
4. 明確なバージョニング規則がある場合のみ、適切なバージョン更新、変更履歴、リリースノート、公開前チェックリストを提案または更新する。規則やリリース対象が確認できない場合は推測で番号を変更しない。
5. ビルド、パッケージ、テスト、ドキュメント、ライセンス、依存関係、互換性、移行、ロールバック、公開設定を確認する。外部公開に必要な認証情報は表示・追加しない。
6. リリース実行、Git tag、GitHub Release、パッケージ公開、デプロイ、秘密情報の変更は、この依頼では行わない。
7. 更新した差分を、実装済み変更との一致、変更履歴・リリースノートの正確さ、認証情報の非混入の観点でレビューする。Critical または High 相当の指摘がある場合は対応し、指摘がなくなるまで手順4〜7を繰り返してから完了とする。

## 完了基準

- リリースの対象範囲、互換性・移行リスク、必須検証が根拠とともに整理されている。
- 更新した変更履歴・リリースノートは実装済み変更と一致している。
- `PR作成` がある場合だけ、準備差分をドラフト PR として提示している。

## 禁止事項

- リリースの公開、タグ作成、デプロイは行わない。
- 規則やリリース対象が確認できない場合は推測で番号を変更しない。
- 外部公開に必要な認証情報は表示・追加しない。
- リリース実行、Git tag、GitHub Release、パッケージ公開、デプロイ、秘密情報の変更は、この依頼では行わない。

## 報告形式

```md
## リリース候補
- <内容>

## 変更内容
- `<path>`: <内容>

## 実行した検証
- `<command>`: 成功 / 失敗 / 未実施（理由）

## セルフレビュー
- 計画: なし / [重大度: Critical / High / Medium / Low] <指摘と対応>
- 差分: なし / [重大度: Critical / High / Medium / Low] <指摘と対応>

## 公開前に残る手動作業
- なし / <内容>

## リスク
- なし / <内容>

## PR
- <URL または未作成理由>
```
