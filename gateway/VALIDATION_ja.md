# 日本語会話 Gateway の検証記録

確認日: 2026-10-12〜13。実装コードを対象とし、公開済みファームウェアの機能保証とは区別します。

## 確認済み

- Gateway: `npm test`（197テスト）、型検査、lint。
- 変更したファイルのformat/checkは成功。Gateway全体のformatは既存の未変更ファイルで失敗する（主にCRLF/LFの差）。そのファイルは本変更では整形していない。
- Firmware: TypeScriptテストビルドと、Gateway Dock / bridge / protocol の53テスト。
- 音声サービス: Python unittest 2テスト。WAV入力、ローカルHTTP、日本語固定、Origin拒否。
- 実際のCodex CLI 0.162.1: 既存サブスク認証を使った日本語の構造化返答を確認。
- 実際のClaude Code 2.1.296: 既存サブスク認証を使った日本語の構造化返答を確認。
- Codex / Claude のサブスク認証状態を公式CLIで確認し、APIキー認証では返答を生成しないことをテスト。
- 実際のLM Studio: 導入済み `google/gemma-4-e4b` を4096コンテキストでロードし、日本語の構造化返答を確認。
- 管理画面: 386px幅と1200px幅の表示、LLM切替・モデル保存・実際のローカル返答テストをブラウザで確認。ブラウザのerror/warnログなし。
- 二重起動時に既存のGatewayを検出し、新しいセッション・音声サーバーを生成しないことを確認。
- HTTP / WebSocketの統合試験: 開始・停止・テキスト送信、設定変更、LLM切替、会話履歴共有、履歴削除、古い本体の管理操作拒否。
- 中断試験: 遅いモデルの旧応答が次の返答・身体操作・履歴へ混入しないこと。
- 音声アダプター試験: ローカルSTTのWAV送信、VOICEVOXのquery/synthesisとPCM変換、既存再生経路との型・データ互換。
- 保存試験: 同時書込み、再起動後の復元、設定変更、履歴削除。破損ファイルを自動上書きしないこと。

## 環境による未確認

- CoreS3のファームウェアビルドを実行したが、Windows環境の `MODDABLE` 未設定で停止。
  Moddable / ESP-IDF を設定した環境で `npm run build:m5stackchan_cores3 -- --mode=release` を実行する必要がある。
- 実機未接続。マイク・スピーカーの品質、物理顔タップ、サーボ、Wi-Fi復帰、書込みは未確認。
- Lemonadeは導入済みCLIの既定ポート13305でサーバーが応答しないため、実モデルの返答は未確認。
  互換APIによる文脈送信とモデル選択はモック通信で検証済み。
- ローカル認識モデルとVOICEVOXが未起動。実際の日本語音声の認識・合成品質は初回セットアップ後に確認する。
  認識モデルのダウンロードや有料音声APIへの接続は検証には含まない。

## 実機受入れ

1. 音声セットアップとVOICEVOX起動後、管理画面で両エンジンが接続済みになる。
2. 本体設定を保存・再起動し、管理画面にCoreS3接続中が表示される。
3. 顔タップと画面の開始でマイクが動き、日本語の質問に返答する。
4. 返答中に顔タップ・画面の中断で音声が止まり、次の質問を受け付ける。
5. LLM切替後とPC再起動後も、直近の会話を覚えている。
6. 表情・控えめなうなずき・視線が、実機の安全な可動範囲で動く。
7. 停止後に音声・動作・古い返答が再開しない。Wi-Fi復帰後も繰り返し操作できる。
